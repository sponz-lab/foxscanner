# 본사 설정 안내 — 한 번만 하면 끝입니다

전국 매장이 **같은 주소 하나**를 씁니다. 매장에서는 계정을 만들거나 파일을 고칠 일이 없습니다. 주소만 열면 됩니다.

설정은 본사에서 한 번만 합니다.

| 할 일 | 누가 | 얼마나 |
|---|---|---|
| 1부 · 주소 만들기 (깃허브) | 본사 1회 | 5분 |
| 2부 · 실시간 합산 켜기 (Firebase) | 본사 1회 | 15분 |
| 매장에서 할 일 | 매장 | 주소 열기 — 매장은 자동으로 잡힘 |

2부를 건너뛰어도 프로그램은 돌아갑니다. 카메라 스캔·검수·반품 리포트 모두 됩니다. 여러 명이 같은 전표를 나눠 찍을 때 수량이 각자 따로 세어질 뿐입니다.

---

## 1부 · 주소 만들기

저장소가 **비공개**이므로 GitHub Pages(유료)가 아니라 무료 호스팅(Cloudflare Pages 권장)에 올립니다. 순서는 [`../deploy/배포안내.md`](../deploy/배포안내.md) 를 따르세요. 끝나면 이런 주소가 생깁니다.

```
https://<프로젝트이름>.pages.dev/start.html
```

이후 프로그램을 고칠 때는 저장소에 push 하면 자동으로 다시 배포됩니다. 주소는 그대로입니다.

---

## 2부 · 실시간 합산 켜기

구글 계정만 있으면 됩니다. **프로젝트 하나로 전국 매장을 다 씁니다.**

### 1단계 · 프로젝트 만들기

1. <https://console.firebase.google.com> 접속 → 구글 로그인
2. **프로젝트 만들기** → 이름 `fjallraven-check` (아무 이름이나 됩니다) → 계속
3. **Google 애널리틱스**는 **사용 안 함** → 프로젝트 만들기 → 계속

### 2단계 · 데이터베이스 만들기

1. 왼쪽 **빌드 → Firestore Database** → **데이터베이스 만들기**
2. 위치 **asia-northeast3 (서울)**
3. **프로덕션 모드로 시작** → 만들기

### 3단계 · 익명 로그인 켜기

매장 직원이 따로 로그인하지 않아도 되게 하는 설정입니다.

1. 왼쪽 **빌드 → Authentication** → **시작하기**
2. **익명** 선택 → **사용 설정** → 저장

### 4단계 · 접근 규칙 넣기

1. **Firestore Database** → 위쪽 **규칙** 탭
2. 내용을 모두 지우고 아래를 붙여넣기 → **게시**

```
rules_version = '2';
service cloud.firestore {
  match /databases/{database}/documents {
    match /stores/{store}/{document=**} {
      allow read, write: if request.auth != null;
    }
  }
}
```

매장별로 폴더가 나뉘므로 다른 매장 자료가 섞이지 않습니다.

### 5단계 · 설정값 가져오기

1. 왼쪽 위 **톱니바퀴 → 프로젝트 설정**
2. **내 앱**에서 웹 아이콘 `</>` → 닉네임 `매장검수` → **앱 등록** (호스팅은 체크 안 함)
3. 화면에 나오는 `firebaseConfig` 값들을 복사

### 6단계 · config.js 에 넣기

저장소의 `config.js` 에서 따옴표 사이의 값만 채운 뒤 commit · push 합니다(자동 배포).

> **파일 전체를 Firebase 화면 내용으로 바꾸지 마세요.** Firebase가 보여 주는 코드에는 `import { initializeApp } …` 과 `const app = initializeApp(firebaseConfig);` 줄이 함께 들어 있는데, 이 줄들이 들어가면 프로그램 전체가 멈춥니다. **따옴표 안의 값 6개만** 옮기면 됩니다.

```js
window.INBOUND_CONFIG = {
  firebase: {
    apiKey:            "AIza...",
    authDomain:        "fjallraven-check.firebaseapp.com",
    projectId:         "fjallraven-check",
    storageBucket:     "fjallraven-check.appspot.com",
    messagingSenderId: "123456789012",
    appId:             "1:123456789012:web:abcdef..."
  }
};
```

1~2분 뒤부터 전국에서 실시간 합산이 켜집니다. **매장 목록은 적지 않습니다.**

## 매장 구분은 어떻게 되나

입고 전표와 반품 코드는 매장별 아이디로 로그인해야 보이는 자료입니다. 그래서 매장 구분도 **그 로그인을 따라갑니다.** 본사가 매장 목록을 관리하거나 직원이 목록에서 매장을 고르는 일이 없습니다.

| 경로 | 매장이 정해지는 방식 |
|---|---|
| PC — 회사 시스템에서 **리스트 가져오기** | 로그인한 매장(화면 상단의 매장명·코드)을 읽어 자동으로 들어갑니다 |
| 휴대폰 — PC 화면의 **참여 QR** 을 카메라로 비춤 | QR 안에 매장과 전표가 들어 있어 그대로 따라옵니다 |
| 둘 다 아닌 경우 | 처음 한 번 자기 매장코드를 입력합니다 (기기에 저장) |

매장별로 자료가 분리되므로 다른 매장 검수 내용은 보이지 않습니다.

## 매장에 알려 줄 내용

**설치 페이지 주소 하나만 보내시면 됩니다.**

```
https://<프로젝트이름>.pages.dev/start.html
```

그 페이지가 매장에서 할 일 네 가지를 차례로 안내합니다.

1. 휴대폰 기본 카메라로 QR을 찍어 검수 프로그램을 연다 (홈 화면에 추가)
2. 매장 PC 크롬 북마크바에 초록 버튼 두 개를 끌어다 놓는다
3. 아침 입고 순서
4. 반품 순서

더 자세한 설명이 필요하면 「매장안내.md」를 함께 전달하시면 됩니다.

## 비용과 규모

Firebase 무료 범위는 하루 쓰기 2만 건, 읽기 5만 건입니다.

- 전표번호를 넣지 않고 혼자 검수하면 서버를 **전혀 쓰지 않습니다**
- 전표번호를 넣고 검수하면 한 건당 대략 100~200회 쓰기가 발생합니다
- 매장 수가 늘어 한도를 넘으면 구글에서 알림이 옵니다. 그때 **Blaze(종량제)** 로 바꾸면 되고, 이 정도 사용량은 월 몇 천 원 수준입니다

지금처럼 몇 개 매장이면 무료 범위 안에서 충분합니다.
